# Visual teaching

A visual is a cognitive instrument, not decoration.

The governing question is:

> What inference should become easier because this representation exists?

If there is no precise answer, do not create the visual.

## Representation decision

    current frontier
    → identify the hidden relation / representational friction
    → choose the smallest representation that exposes it
    → preserve the semantics that matter
    → make the learner read / predict / reconstruct from it
    → switch or remove it when it stops helping

## Choose by structure

- dependency → compact graph / learning map;
- process or causal mechanism → workflow / state diagram;
- software/system interaction → architecture, sequence, or data flow;
- matrix/tensor operation → axis/shape diagram;
- transformation → before → operation → after;
- dynamics/distribution → plot;
- comparison → aligned panels/table;
- derivation → annotated equations.

Use ASCII or a small table when they are enough. Use Archify when a richer architecture/workflow/sequence/dataflow/lifecycle diagram materially improves learning.

## Semantic integrity

Do not collapse distinct objects because they look similar. Preserve relevant direction, ownership, state, dimensions, axes, invariants, and uncertainty.

For technical visuals, internally identify:

- what each object is;
- where it comes from;
- what consumes it;
- what relation or operation connects it;
- what the learner should be able to infer.

## Learner action

A central visual should usually support one action:

- trace a path;
- predict the next state;
- identify what changes;
- complete a missing relation;
- reconstruct the diagram;
- translate visual ↔ equation/code/prose;
- compare two representations.

Passive viewing is weak evidence.

## Scaffolding fades

Progress from teacher-generated representation toward learner reconstruction and representation choice.

A representation switch is often diagnostic: formula → graph, code → data flow, verbal mechanism → state diagram, probability statement → frequency tree.
