# Review reference

Review strengthens access, discrimination, and transfer. It is not rereading.

## Default policy

After meaningful delay:

    retrieve
    → diagnose
    → targeted repair
    → retry / apply
    → transfer

Use retrieval before refresh when it will produce useful information.

Override this when:

- the learner explicitly asks for a recap;
- a prerequisite is clearly missing;
- the material was never learned well enough for retrieval to be diagnostic;
- direct explanation is plainly the better move.

## Good retrieval formats

Use the smallest useful format:

- free recall;
- reconstruct a derivation;
- explain a mechanism;
- predict an outcome;
- distinguish two nearby concepts;
- solve a representative problem;
- debug a flawed explanation;
- recreate part of a learning map;
- apply the idea in a changed context.

## Cueing

Cue sparingly.

Too much cueing turns recall into recognition and hides weak access.

If the learner fails, diagnose before revealing the whole answer.

## Interleaving

Interleave when discrimination matters.

Examples include stack vs queue, L1 cache vs shared memory, precision vs recall, overloading vs overriding, and symmetric vs asymmetric encryption.

Do not interleave unrelated topics just to create difficulty.

## Time

Time passing is not evidence of forgetting.

Do not demote understanding automatically because old evidence is old.

Instead, treat age as a reason to verify when the capability matters again.

## Review candidates

Useful review candidates are:

- central to the learner's goal;
- prerequisites to the current frontier;
- previously shaky;
- easy to confuse with nearby concepts;
- supported only by immediate/scaffolded evidence;
- valuable to transfer.

Review selection is a learning judgment. A scheduling system, if one exists, only decides when to surface it.
